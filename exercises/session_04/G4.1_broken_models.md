# G4.1 — Diagnose and fix broken models

| | |
|---|---|
| **Learning objective** | find the cause of a failed or wrong simulation from the log, and fix it in the model rather than in the solver settings |
| **Prerequisites** | Session 4 §4.2–4.4 (log, initialization, events); M01 and M02 (Sessions 1–2) |
| **Starting files** | `EnergyTraining.Examples.Broken` (in the course library), `exercises/session_04/S04_G1_Fixes_start.mo` |
| **Expected duration** | 20 min |
| **Expected outcome** | three models that simulate correctly, and a written diagnosis for each (symptom, log line, cause, fix) |

## Instructions

`EnergyTraining.Examples.Broken` holds three models with **one deliberate error each**:
`MissingInitialCondition` (M02), `OverdeterminedInitialization` (M01) and
`ChatteringThermostat` (M01 with an on/off heater). The documentation of each model says what it
is meant to do.

1. Simulate each model in OMEdit (or from Python, see below). Copy the warning or error that
   matters into the table. One of the models **runs without errors** and is still wrong: compare
   its result with what the documentation promises. `ChatteringThermostat` simulates only
   5000 s, on purpose.
2. For each model, fill in:

   | Model | Symptom | Log line | Cause | Fix |
   |-------|---------|----------|-------|-----|
   | `MissingInitialCondition` | | | | |
   | `OverdeterminedInitialization` | | | | |
   | `ChatteringThermostat` | | | | |

3. Write the fixes in a copy of `S04_G1_Fixes_start.mo`. The first two fixes **extend** the
   broken model: an extended model may add equations, and a modifier in the `extends` clause may
   change an attribute of an inherited variable. The third is a new model in which you write
   the heater rule with a `when` equation (§5.2 of the lesson).
4. Simulate your fixes. `MissingInitialCondition` must reproduce
   `EnergyTraining.Examples.S03_ZoneRCStep`. `OverdeterminedInitialization` must stay at 20 °C
   for 72 h. `Thermostat` must run for 24 h with the zone temperature between 19.5 and 20.5 °C
   once it has reached 20.5 °C. Count its state events with the simulation flag
   `-lv=LOG_STATS`.

From Python, the log of a run is in `run.log`:

```python
from energy_training.omc.runner import simulate

run = simulate(
    "EnergyTraining.Examples.Broken.ChatteringThermostat",
    out_dir="output/s04_g1",
    simflags="-lv=LOG_STATS -noEventEmit",
)
print(run.log)
```

## Extension activity

`EnergyTraining.Examples.Broken.DivisionByZero` is an electric heater on a water flow whose
pump stops after 30 min. Diagnose the failure. Is the error in the solver or in the model? What
physical quantity is missing? Write a fix that still runs when the pump is off. Keep in mind how
a switch should react when a flow drops to exactly zero.
